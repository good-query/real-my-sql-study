# 0. 학습 목적
- 테이블 풀-아웃이 무엇인지 이해한다.
- 테이블 풀-아웃 최적화가 가능한 조건에 대하여 이해한다.

# 1. 테이블 풀-아웃 (table pull-out)이란?
세미조인 서브쿼리를 하나의 조인 쿼리문으로 바꾸는 최적화 기법을 말한다.
이를 위해 서브 쿼리의 내부 테이블을 아우터 쿼리로 끄집어내서 해당 기법을 `테이블 풀 아웃`이라 부른다. 

## (1) 예시
먼저 다음과 같은 *`d009` 부서에 속한 모든 직원을  조회하라* 라는 세미조인 서브쿼리를 실행한다고 하자.
```sql
SELECT * from employees e
WHERE e. emp_no
IN (
	SELECT de.emp_no 
	FROM dept_emp de 
	WHERE de.dept_no=  'd009' 
	)
```

위의 쿼리문에 대해  `테이블 풀-아웃` 최적화를 진행하면 다음과 같이 된다.
```sql
SELECT * 
FROM emplyoees e
JOIN dept_emp de
WHERE (( e.emp_no = de.emp_no) AND de.dept_no = 'd009')
```

# 2. 실행 계획 상 표시
실행 계획을 보면 다음과 같다.

```sql
id   select_type     table    type      key        rows     Extra
1    SIMPLE           e        ref      PRIMARY   46012     Using Index
1    SIMPLE           de       eq_ref   PRIMARY   1         NULL
```
서브쿼리 그대로 진행했으면 id가 2개가 나왔어야 했는데, 해당 쿼리문은 id = 1로 하나인 것을 확인할 수 있다. 덕분에 쿼리가 하나로 합쳐졌음을 알 수 있다. 다만 `테이블 풀-아웃`이 사용 되었음을 표시하는 문구는 따로 뜨지 않는다.

> [!info] 만약 바뀐 쿼리문을 보고 싶다면? 
> `Explain` 명령을 실행한 직후 `SHOW WARNINGS` 명령으로 옵티마이저가 재작성한 쿼리를 살펴볼 수있다.

# 3. 테이블 풀-아웃을 사용할 수 있는 조건
1. 세미조인의 정의를 만족하는 서브쿼리에서만 사용 가능하다.
2. 외부 테이블 레코드 하나 당 서브쿼리의 결과가 `유니크 인덱스`나 `PK` 룩업으로 오직 1개만 나와야 한다. 

### 2번 조건에 대한 예시
 *'이름이 Matt인 사원 중에서 1995년 1월 1일부터 30일 사이에 직급이 변경된 적이 있는 사원을 조회해라'* 라는 쿼리를 이행한다고 해보자. 테이블 관계도와 쿼리문은 다음과 같다.
![image.png](https://raw.githubusercontent.com/dalcheonroadhead/img-cloud/main/2025-07/20250806002040.png)

```sql
SELECT *
FROM employees e
WHERE e.first_name= 'Matt'
AND e.emp_no IN (
	SELECT t.emp_no
	FROM titles t
	WHERE t.from_date BETWEEN '1995-01-01' AND '1995-01-30'
)
```

테이블 관계도를 보면, `(직급 바뀐 날짜, 사번)`로 유니크 인덱스도 성립함을 알 수 있다. 서브 쿼리문 자체도 직급 바뀐 날짜와 사번이 각각 WHERE 절과 SELECT 절에 쓰이고 있음으로, 해당 유니크 인덱스를 쓸 수 있는 환경이다. 만약 *'사원의 진급은 현 직급은 한 달 이상 직무 수행을 해야 가능하다.'* 라는 제약 조건이 있다면, 위의 쿼리문은 **`테이블 풀-아웃`의 2번 조건을 만족하기에** 최적화 가능하게 된다.

### 2번 조건은 왜 필요한가? 
세미 조인 쿼리는 외부 테이블과 내부테이블의 조인 조건 일치여부만 화인하면 된다. 하지만 만약 외부 테이블 레코드 하나 당 일치하는 내부 테이블 레코드가 2개 이상이라면, 조인을 했을 떄, 굳이 알 필요 없는 중복 행이 발생한다는 뜻이다. 이는 최적화하는 이유를 잃게 만든다. 

# 핵심 요약
1. `테이블 풀-아웃`이란 세미조인 형태의 서브쿼리를 하나의 조인문으로 변환하는 최적화 기법이다. 이를 위해 서브 쿼리의 내부 테이블을 아우터 쿼리로 끄집어 내는 작업을 해서 이름이 테이블 풀-아웃이다.
   
2. 테이플 풀-아웃 최적화가 되었어도, `실행 계획 상`  따로 표시되지 않는다. 다만 id 값이 병합되는 것 (원래 id가 2개로 나눠져야 했지만 1개로 되는 것 등)으로 확인한다. 만약 개발자가 변환된 쿼리문을 보고 싶으면 explain 명령어 실행 직후 `SHOW WARNING`을 실행하면 변환된 쿼리문이 보인다.
   
3. `테이블 풀 아웃을 사용할 수 있는 조건`은 다음과 같다.
	1. 세미조인의 정의를 만족하는 서브쿼리여야 한다.
	2. 외부 테이블 레코드 하나당 서브쿼리의 결과가 유니크 인덱스나 PK 룩업으로 하나여야 한다. 
	   
4. 조건 중 2번이 생긴 이유는, 만약 외부 테이블 레코드 하나당 서브 쿼리 결과가 2개 이상이면 조인 레코드가 2개 이상으로 생길 것이기 때문이다. 내부 테이블 상 일치하는 레코드의 존재 유무만 찾으면 되는 세미 조인 쿼리 상 이러한 중복 레코드는 불필요한 낭비이다.
