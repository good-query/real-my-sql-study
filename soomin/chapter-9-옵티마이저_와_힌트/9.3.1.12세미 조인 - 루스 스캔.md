# 0. 학습 목적
- 세미 조인 최적화 기법으로서 루스 인덱스 스캔은 어떻게 쓰이는지 이해한다.
- 해당 기법의 원리를 이해한다.

# 1. 루스 스캔 (Loose Scan) 이란?
해당 방식은 GROUP BY 최적화 시 사용하던 `Loose Index Scan`를 활용한 최적화 기법이다. 
드라이빙 테이블의 인덱스를 이용하여 루스 인덱스 스캔 후, 조인 조건 상 일치하는 레코드가 있을 때만 드리븐 테이블로 랜덤 접근 한다.

# 2. 작동 원리
1. 내부 테이블을 드라이빙 테이블로서 활용한다. (이때 내부 테이블은 루스 인덱스 스캔을 쓸 수 있는 인덱스가 존재해야함.)
2. 내부 테이블에서 루스 인덱스 스캔을 하여, 유효한 레코드 발견 시에만 외부 테이블로 랜덤 접근하여 쿼리문 상 필요한 작업을 진행한다. 

## (1) 예시 
![erd 그림](https://raw.githubusercontent.com/dalcheonroadhead/img-cloud/main/2025-07/20250806150313.png)
다음과 같이 사원과 부서 테이블이 존재하고 교차 테이블로 `emp_dept`라는 테이블이 존재한다. 해당 교차 테이블은 `(dept_no, emp_no)`로 복합 PK 를 지니고 있다고 해보자. 이때 개발자는 *'emp_dept에 존재하는 모든 부서의 정보를 조회하라'*는 쿼리를 실행해야 한다. 쿼리문으로 나타내면 다음과 같다.

```sql
SELECT *
FROM departments d WHERE d.dept_no
IN (
	SELECT de.dept_no
	FROM dept_emp de
   )
```

`emp_dept` 교차 테이블의 전체 레코드는 3만 건이지만, 부서는 단 9건만 존재한다고 하자. 이떄는 교차 테이블의 PK로 루스 인덱스 스캔을 타면 된다. 복합키의 왼쪽 컬럼인 부서 번호를 통해, 최초 조우하는 부서 번호에 대해서만 외부 테이블로의 접근을 하여 정보를 가져온다. 그 이후 동일한 부서 번호는 모두 건너 뛴다.
![image.png](https://raw.githubusercontent.com/dalcheonroadhead/img-cloud/main/2025-07/20250806151722.png)

이렇게 되면 불필요하게 내부 테이블의 모든 레코드에 대하여 외부 테이블을 확인하는 것 없이 단 9건만 외부 테이블 접근을 하면 된다.

# 3. 실행 계획상 표시
```sql
id    table    type    key        rows    Extra
1     de       index   PRIMARY    331143  Using index; Loose Scan
1     d        eq_ref  PRIMARY    1       NULL
```

실행 계획 상 확인하면 위에서 배웠던 동작 원리를 더 잘 파악할 수 있다.

1. 내부 테이블이 드라이빙 테이블, 외부 테이블이 드리븐 테이블이 되었다.
2. 내부 테이블에 관하여 Loose Scan을 진행했다. 

# 핵심 요약
1. `Loose Scan`이란 Group By 최적화할 떄 쓰던 Loose Index Scan을 세미 조인 최적화에 활용하는 방법이다.
2. `동작 원리`는 다음과 같다.
	1. 내부 테이블을 드라이빙 테이블, 외부 테이블을 드리븐 테이블로 둔다.
	2. 내부 테이블에는 Loose Index Scan을 쓸 수 있는 적절한 인덱스가 존재한다고 가정한다.
	3. Loose Index Scan을 통해 내부 테이블에서 유효한 레코드를 확인했을 때만 외부 테이블에 접근하여 쿼리문 상 필요한 작업을 진행한다.
