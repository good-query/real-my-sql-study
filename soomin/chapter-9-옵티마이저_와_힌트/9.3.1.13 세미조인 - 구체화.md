# 0. 학습 목적
1. 세미조인 최적화 기법으로서의 구체화에 대해 이해한다.

# 1. 구체화 (Materialization) 이란? 
서브쿼리 결과를 내부 임시 테이블에 저장하고 이를 활용해 쿼리문을 수행하는 최적화 기법이다. 

## (1) 일반적인 구체화 방식과의 차이점은?
1. 조인 방향이 자유로운가? 
2. 중복 레코드 제거가 필수인가 옵션인가? 

![image.png](https://raw.githubusercontent.com/dalcheonroadhead/img-cloud/main/2025-07/20250806155723.png)
```sql
EXPLAIN
SELECT *
FROM employees e
WHERE e.emp_no 
IN  (
		SELECT de.emp_no
		FROM dept_emp de
		WHERE de.from_date = '1995-01-01'
	)
```

위와 같은 테이블 구조에서 *'1995-01-01에 조직이 변경된 사원들을 모두 조회하라'* 라는 쿼리문을 실행한다고 해보자.

### A. 조인 방향
일반 Materialization은 `외부 테이블 (드라이빙)` -> `내부 임시 테이블 (드리븐)` 방향으로 조인이 진행된다.
```sql
id   select_type     table        type      key            ref
1    SIMPLE           e           ALL       PRIMARY        
1    SIMPLE          <subquery>   ALL       NULL         
2    MATERIALIZATION  de          ref       ix_from_date   const
```
위의 실행 계획을 보면 먼저 de 테이블에 대한 구체화를 작업했지만, 이후에는 구체화한 임시테이블을 사용하지 않고, 외부 테이블인 e를 먼저 확인한 후 임시 테이블을 보는 모습을 볼 수 있다.

반면 세미조인의 구체화 기법은 옵티마이저가 두 테이블의 선택도를 확인해 고를 수 있다.
공식 문서에서는 `Materialization-scan`과 `Materialization-lookup`으로 소개한다.

- `Materialization-scan`
  : *내부 임시 테이블* -> *외부 테이블* 
  세미 조인 구체화 기법에서는 내부 임시 테이블을 만들 때 **유니크 제약조건**이 필수적으로 적용된다는 점을 이용한다. 내부 임시 테이블의 레코드 하나마다 외부 테이블을 탐색하여 쿼리 결과물을 만든다.

- `Materialization-lookup`
  : 외부 테이블 -> 내부 임시 테이블
  만약 외부 테이블에 적절한 인덱스가 있어서 카디널리티를 낮출 수 있다면, 외부 테이블을 드라이빙 테이블로 진행한다. 

### B. 중복 제거 
`일반 구체화 기법`은 중복 제거가 필수가 아니다. 따라서 중복된 데이터가 임시 테이블에 담길 수 있다. 
반면 `세미 조인의 구체화 기법`은 세미조인 상 의미적 중복이 있으면 안되기 때문에, PK나 아니면 조인 컬럼을 활용한 유니크 제약 조건을 임시 테이블에 설정한다.

# 2. 동작 원리 
1. 서브 쿼리를 실행한 후 그 결과를 내부 임시 테이블에 저장한다. (레코드 중복 제거)
2. 다음 중 하나의 기법을 선택하여 드라이빙 테이블과 드리븐 테이블을 정한다.
	1. 내부 임시 테이블의 레코드 하나 당 외부 테이블을 탐색 후 원하는 결과를 찾는다.
	2. 외부 테이블의 레코드 하나 당 내부 임시 테이블을 탐색 한다.

## (1) 예시 

> 여기서는 책에 나와있는 대로, 내부 임시 테이블이 드라이빙 테이블이 되는 예시를 알아보자. 

![image.png](https://raw.githubusercontent.com/dalcheonroadhead/img-cloud/main/2025-07/20250806155723.png)
```sql
EXPLAIN
SELECT *
FROM employees e
WHERE e.emp_no 
IN  (
		SELECT de.emp_no
		FROM dept_emp de
		WHERE de.from_date = '1995-01-01'
	)
```

위의 쿼리문은 외부 테이블에 대한 적절한 필터링 조건 자체가 없다. 따라서 일반 구체화 기법을 사용하면 외부 테이블인 사원 테이블을 전체 순회하며 레코드 하나 당 내부 테이블을 또 전체 순회해야 한다.
만약 `세미조인 - 구체화 기법`으로 최적화 한다면 임시 테이블에 결과를 저장한 후, 임시 테이블의 레코드 하나 당 외부 테이블을 탐색하면 되니까 랜덤 접근 수가 획기적으로 줄어든다.

# 3. 실행 계획 상 표시

```sql
id   select_type     table        type      key            ref
1    SIMPLE          <subquery>   ALL       NULL           <subquery>.emp_no
1    SIMPLE           e           eq_ref    NULL           NULL
2    MATERIALIZATION  de          ref       ix_from_date   const
```

실행 계획을 봐도, 구체화 이후에 바로 임시 테이블을 먼저 탐색함을 알 수 있다. 

# 4. 특징
1. 상관 서브쿼리가 아니여야 쓸 수 있다.
2. 서브 쿼리 내에 GROUP BY나 집합 함수들이 사용되어도 쓸 수 있다.

상관 서브쿼리의 결과를 임시 테이블에 저장하려면 외부 테이블을 확인해야 한다. 외부 테이블을 꼭 확인해야 할 상황이라면 그냥 조인을 실행하여 쿼리를 실행하면 되기에, 굳이 임시 테이블을 쓰는 효율성이 떨어진다. 
임시 테이블로 결과를 저장하는 과정이 있기 떄문에 쿼리문에 `GROUP BY`나 `집합 함수`는 사용되어도 된다.

# 5. 핵심 요약
1. `세미 조인의 구체화 기법`은 서브 쿼리 결과를 임시 테이블에 저장하는 최적화 기법이다.
2. `일반 구체화 기법과의 차이점`은 일반 구체화 기법은 조인 방향이 정해져 있고, 내부 임시 테이블 내의 중복 제거 과정이 필수로 들어있지 않지만, 세미조인 구체화기법은 조인 방향을 옵티마이저가 선택도 확인 후 정할 수 있고, 내부 임시 테이블을 만들 때, 유니크 제약 조건으로 필요한 컬럼에 대한 유일성을 보장한다는 것이다.
3. 세미 조인 구체화 기법은 `상관 쿼리이면 불가능`, `GROUP BY 나 집합 함수가 서브쿼리에 포함되어 가능` 이라는 특징을 가진다.
