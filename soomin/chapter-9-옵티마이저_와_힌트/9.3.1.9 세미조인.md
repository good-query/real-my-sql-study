# 0. 학습 목적
1. 세미 조인이 무엇인지 이해한다.
2. 세미 조인 최적화 기능이 없었을 떄, 세미 조인을 어떻게 처리했는지를 이해한다.
3. 세미 조인 최적화의 종류와 양상이 어떻게 되는지 이해한다.

# 1. 세미 조인 (Semi Join) 이란?
외부 테이블의 레코드마다 그것과 조인 조건상 일치하는 레코드가 내부 테이블안에 있는지 없는지 여부만 알면 되는 쿼리문을 말한다. 일치 레코드 존재 여부만 확인하면 되므로, 조인을 진행하지 않는다.

# 2. 세미조인 최적화 기능이 없었을 때 실행계획

```sql
SELECT *
FROM employees e
where e.emp_no 
IN  (
		SELECT de.emp_no 
		FROM dept_emp de
		WHERE de.from_date = '1995-01-01'
	) 
```
위의 쿼리문은 *'1995년 1월 1일에 입사한 사원들을 전부 출력하라. '* 라는 쿼리문이다. 

만약 서브쿼리 최적화 기능이 없었다면 다음과 같이 동작한다.
1. 서브 쿼리문 계산 
2. 외부 테이블인 `employees`의 모든 행마다 서브 쿼리의 `emp_no`와 일치하는지 확인

```sql
-- EXPLAIN 썼을 때, 실행 계획
id   select_type     table    type    key    rows
1    PRIMARY_KEY     e        ALL     NULL   300363
2    SUBQUERY        de       ref  ix_fromdate 57 
```

실행계획을 봐도  서브쿼리를 먼저 만들어서 후보 레코드가 57개로 줄어들었으나, 외부 테이블 전체인 300,363 건을 전부 다시 확인하는 모습을 볼 수 있다.

위와 같이, 세미조인에서 비효율적인 실행계획을 타파하기 위해, 다음의 세미조인 최적화 기능들이 등장했다.

# 3. 세미조인 최적화 기능의 종류와 양상
먼저 `동등 세미 조인`과 `안티 세미 조인 (비동등 세미 조인)`으로 나누어 생각해보자. 

동등 세미 조인은 옵티마이저의 고급 최적화 기능 중 하나인 `semijoin` 최적화 옵션을 사용하여 실행 계획을 최적화할 수 있다. 반면, 비동등 세미 조인은 해당 방법이 불가능하다. 표로 도식화하면 다음과 같다.

| 분류         | 동등 세미 조인                                                        | 안티 세미 조인                                |
| ---------- | --------------------------------------------------------------- | --------------------------------------- |
| 가능한 최적화 전략 | 옵티마이저 옵션 (세미 조인 최적화)<br>IN-to-EXISTS 최적화<br>MATERIALIZATION 최적화 | IN-to-EXISTS 최적화<br>MATERIALIZATION 최적화 |

여기서 동등 세미조인만 쓸 수 있는 `세미 조인 최적화`의 종류는 다음과 같다.
- [[테이블 풀-아웃 (table pull-out)]]
- Duplication Weed-out
- First Match
- Loose Scan
- Materialization

> [!info] 대분류의 Materialization 과 고급 최적화 옵션의 Materialization의 차이
> 퍼플렉시티에게 물어봐도 대답이 모호하긴 한데, 일단 적어놓는다. 나중에 더 자세히 알게되면 상세히 적겠다.
> 대분류의 `구체화`는 서브 쿼리를 실행하여 결과 자체를 임시테이블에 넣는 방식이라고 한다.
> 반면 고급최적화 옵션의 `구체화`는 서브 쿼리를 세미조인 형태로 변환한 후 임시 테이블에 넣는다. 따라서 후자는 임시테이블을 만들 때, `first_match`나 table pull-out 등 다른 최적화 기능을 복수로 적용할 수 있는 반면 전자는 그게 안된다고 한다.

# 4. 핵심 요약
1. `세미 조인(semijoin)`이란 외부 테이블의 레코드마다 그것과 조인 조건상 일치하는 레코드가 내부 테이블에 있는지 없는지 여부만 체크하면 되는 쿼리문을 말한다. 
2. `세미조인 최적화 기능이 없었을 땐`, 서브 쿼리문 계산해서 조인 후보군이 추려져도, 외부 테이블의 모든 행을 돌며, 서브 쿼리 결과와 일치하는 레코드가 있는지 다 확인해야 했다.
3. 세미조인 최적화 기능이 도입되었다. 이떄 `동등 세미 조인`인 경우와 `안티 세미 조인`인 경우 적용할 수 있는 세미조인 최적화 방식에 차이가 있는데, 동등 세미 조인만이 옵티마이져 옵션에 있는 `semijoin` 옵션의 최적화 기능으로 최적화 할 수 있다.

# 5. 부록

### A. 모르는 것 정리
- `동등 세미 조인`
  : 외부 테이블과 내부 테이블 조인 조건이 ` = ` 이거나 `IN` 인 세미 조인
  
- `안티 세미 조인`
  : 외부 테이블과 내부 테이블의 조인 조건이 `!=` 이거나 `NOT IN`인 세미 조인

- `실행 계획 읽는 법`
  1. id가 큰 것이 읽는 우선순위가 높다. 즉 id = 2가 id = 1보다 먼저 실행되는 계획이다.
  2. 동일 id에서는 상대적으로 위에 표기된 것이 아래 표기된 것보다 실행 우선순위가 높다. 

- `실행 계획에서 id란?`
  : id는 쿼리 속 select 문에 대한 식별자이다. 사용자가 쿼리문에 적은 식별자보다 id의 넘버링이 작을 수  있는데, 이는 옵티마이저가 복수의 select를 하나의 select로 변환하여 최적화한 것이다.
